# INTEGRALIS.md — the platform this squad came from

This squad was generated by **Integralis**. This file is the contract between the squad in this repo and
the Integralis platform: what is available to you, and the one duty that will not happen unless you do it.

Read it once per session. It ships in every squad, so it is here whatever else was selected.

## The two halves

**Half one — the files.** The `agents/`, `skills/`, and knowledge cards in this repo. You already have
them. Start at `AGENTS.md`, then `skills/using-the-squad/SKILL.md`.

**Half two — the recording.** Integralis compares what the squad *prescribes* against what *actually
happened*: which docs really ran, in what order, what was asked, how the turn ended. That comparison
is the platform's real output — per-doc usage, flow-vs-reality divergence, an advisor that improves
docs from evidence.

It is derived **entirely from calls you make**. Nothing observes you passively. If nobody reports,
nothing errors: the screens just stay empty, which the owner of this project reads as "my squad is
not being used".

**Recording is part of doing the work, not an optional extra.** Treat it the way you treat committing.

## Your duty, in four calls per prompt

If the Integralis MCP server is connected, then for **every user prompt**:

1. `report_runs` — `status: "open"`, a `session_id` stable for the whole conversation, and `run_seq`
   taken from `capture_status`.
2. Work. Remember which squad doc paths you actually read.
3. `report_usage` — those paths, **before** the closing run call.
4. `report_runs` — same `session_id`, same `run_seq`, the real ending: `completed`, `interrupted`, or
   `superseded`.

`session_id` must not change between prompts in one conversation; a new id per prompt turns every
prompt into its own session and destroys the flow. Never guess `run_seq` — a collision does not fail,
it silently overwrites the earlier run. `capture_status` returns the correct next value per session.

**This is per prompt, not a setup step you finish once.** The way it fails in practice: capture gets
configured, verified once, and then never done again while the real work happens — no error, just a
dashboard quietly going stale. So `install_capture` returns `reminder_files`: write every one of them,
first, before other work. They put this obligation in a file your host loads on its own (a project
skill, an always-applied rule, a `CLAUDE.md` stanza) so it does not depend on your memory. Once
reporting is overdue, every Integralis tool response also carries a `capture_health` nudge.

Reporting everything as `completed` is worse than not reporting: it claims a clean flow that never
happened, and the divergence report is then built on a fiction.

## No CLI required

There is a `npx integralis` CLI. It is a convenience for a persistent developer machine, never a
requirement. The server needs exactly one thing to record: an authenticated MCP `tools/call`.

If this project runs on a hosted or ephemeral host — Replit, a browser IDE, a CI job, a cloud dev
container — do not try to install a CLI that will be gone next turn. Call `install_capture`,
declaring honestly what you can do (`can_run_shell`, `can_write_files`; both default to false), and
take the route it hands you. On these hosts that is `agent_reported`: the four calls above, needing
no shell, no disk, and no new credential.

Agent-reported capture is **lower fidelity** than CLI capture, and Integralis says so rather than
pretending otherwise: an agent cannot observe that it was itself interrupted, only a transcript can.
So endings on this route are inferred. Structure, counts, and doc flow are exact.

If a credential is genuinely needed on a host with no browser, `npx @integralis/cli login --device` prints
a short code a human approves from any browser, including a phone. Never ask anyone to paste a token
into a chat.

Everything is free except `improve_document`, which spends credits and is safety-gated.

## Consent is not yours to change

Two independent tiers, both enforced server-side on every capture call:

| Tier | Scope | Default |
|---|---|---|
| Metadata — doc paths, session ids, timings, commit anchors | per project | **ON** |
| Prompt text — the words of the prompt, and summaries | per account **and** project | **OFF** |

With metadata off, capture is refused (422) and you should say so plainly rather than retrying. With
text off, `prompt`/`summary` are dropped on arrival.

Both are the user's switches. Do not work around either. Do not ask a user to enable text capture so
a screen looks fuller. Do not smuggle prompt text through a metadata field such as `source` or
`doc_path`. If a tier being off is genuinely blocking something the user asked for, name the screen
they would change it on and what it enables, and let them decide.

## The rest of the platform

| I want to… | Call |
|---|---|
| Find this project's squad id | `list_squads` (archived ones: `list_archived_squads`) |
| Pull squad file updates | `sync_squad` — deltas only, no timestamp to remember |
| Recover what an earlier session decided | `read_memory`, and `record_memory` when you decide something |
| Search this project's knowledge base | `search_knowledge` |
| Understand why a doc exists | `explain_doc` |
| Check recording is actually working | `capture_status` |
| Bring an existing codebase into Integralis | `extract_project_guide`, then `import_project` |

A regular account acts only on squads it owns. A `squad_id` you were not given does not become yours
by being syntactically valid.

## If the MCP server is not connected

Then there is nothing to report to, and that is fine — say so once if it is relevant and carry on with
the files. Do not fabricate capture, and do not treat a missing server as a reason to skip the squad's
own working agreement.
